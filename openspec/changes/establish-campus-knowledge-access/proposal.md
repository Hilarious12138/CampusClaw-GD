## Why

CampusClaw-GD 需要先建立可信的班级教学材料入口，让教师上传的内容成为本班可查的知识库数据，同时阻止未登录、学生上传与跨班级访问。

## What Changes

- 教师和学生使用预先配置的账号密码登录；未登录访问受保护页面转到登录页，受保护 API 返回未认证错误。
- 服务端识别教师/学生角色，只有本班教师可以上传材料；学生直接调用接口同样被拒绝。
- 以班级为数据边界，所有列表与材料读取均在服务端验证成员关系并过滤。
- 教师上传材料后解析文本并持久化到知识库；本班材料列表从数据库查询，不展示静态样例冒充结果。
- 密码只保存安全哈希，密钥只来自服务端环境变量。
- 预置 A/B 两班、每班教师和学生各一名、每班一份合成教学材料及正文；种子可重复运行且不覆盖已有修改。
- 规划 Docker Compose 启动应用与数据库，持久化数据；提供匿名 GET /health 与容器 healthcheck，数据库不可用时健康检查失败。

## Capabilities

### New Capabilities

- `auth-upload`：登录、角色鉴权、班级材料隔离、教师上传解析入库、预置样本及运行健康检查的完整闭环。

### Modified Capabilities

无。本项目尚无已落地能力。

## Impact

未来涉及登录页面、服务端会话与鉴权、班级成员关系、材料与知识库内容存储、解析器及验证用例。本轮已授权实施迭代 1；独立实现，不修改课表示例及其数据库。

## Non-Goals

迭代 1 执行本变更。不做检索问答、AI 对话、作业提交与批改、注册与找回密码，也不扩展账号或班级管理后台。知识库入库指存储材料元信息及解析正文，本次不要求向量化或模型调用。
