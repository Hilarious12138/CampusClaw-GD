## Purpose

为 CampusClaw-GD 建立以班级为边界的教学材料知识库入口，使教师和学生能够经过账号认证后访问本班材料，仅授权教师可以上传并解析入库，同时保证密码与服务端密钥不会以明文或客户端配置泄露。

## ADDED Requirements

### Requirement: R1 登录与会话
系统 SHALL 支持预置教师和学生账号通过账号密码登录，由服务端确定身份、角色与班级成员关系。

#### Scenario: 两类角色成功登录
- **WHEN** 教师或学生分别提交其有效账号和密码
- **THEN** 建立对应身份的有效会话，角色来自服务端记录而非客户端选择

#### Scenario: 错误凭证
- **WHEN** 提交错误账号或密码
- **THEN** 不建立会话，返回统一认证失败提示，不泄露账号是否存在

### Requirement: 未认证访问受保护资源
系统 SHALL 将未登录或会话失效的受保护页面访问引导到登录页，并对受保护 API 返回 401，不能只依赖页面跳转保护数据。

#### Scenario: 未登录访问页面
- **WHEN** 未登录用户直接打开班级材料页面
- **THEN** 被引导到登录页，页面不得显示受保护材料

#### Scenario: 无效会话直接请求接口
- **WHEN** 请求材料列表或上传接口时没有有效会话
- **THEN** 返回 401，不读取受保护内容、不产生上传记录

### Requirement: R2 角色权限
系统 MUST 在服务端检查角色和班级授权；学生只可读取授权班级材料，不得上传，客户端隐藏按钮不构成权限控制。

#### Scenario: 本班教师上传
- **WHEN** 有效教师会话向其所属班级提交符合约束的教学材料
- **THEN** 允许进入文件校验及解析入库流程

#### Scenario: 学生绕过页面上传
- **WHEN** 学生直接调用上传接口，或在请求中伪造 teacher 角色及教师 ID
- **THEN** 返回 403，且不产生材料、知识库正文或持久化上传产物

### Requirement: R3 查询层班级隔离
系统 MUST 在服务端校验班级成员关系并过滤数据，所有材料列表、正文读取及提供的文件访问入口都必须受同一边界约束。

#### Scenario: A 班列表不含 B 班
- **WHEN** 仅属于 A 班的教师或学生查询 A 班材料列表
- **THEN** 结果只包含 A 班材料，不包含 B 班记录、正文或文件地址

#### Scenario: 猜测其他班级材料 ID
- **WHEN** 仅属于 A 班的用户请求 B 班列表或材料，或把 B 班材料 ID 放入 A 班路径
- **THEN** 返回 404，不透露材料信息，也不返回可绕过权限的公开链接

#### Scenario: 教师跨班上传
- **WHEN** 仅属于 A 班的教师向 B 班提交上传请求
- **THEN** 返回 404，不为 B 班写入任何材料

### Requirement: R4 上传解析与持久化入库
系统 SHALL 将授权教师上传的有效材料解析成非空正文，并持久化元信息、班级归属、上传者和正文；只有全部提交成功才能报告上传成功。

#### Scenario: 材料成功入库
- **WHEN** 本班教师上传有效材料且解析和数据库提交成功
- **THEN** 返回 201 与材料 ID，知识库中存在对应正文和班级归属，本班列表重新查库可见该记录

#### Scenario: 刷新和重启后查询
- **WHEN** 上传成功后刷新页面或重启服务，再由本班教师或学生查询
- **THEN** 数据库中的材料记录仍可见，授权正文可读，不依赖前端临时数组

#### Scenario: 格式不支持或文件超限
- **WHEN** 文件不是 UTF-8 .txt/.md 文本，或单文件超过 10 MiB
- **THEN** 分别返回 415 或 413，不报告上传成功、不创建可用知识库记录

#### Scenario: 解析失败或无有效正文
- **WHEN** 文件损坏、解析失败或无法提取非空正文
- **THEN** 返回 422，给出可理解的失败提示，不留下冒充成功的材料，清理临时产物

#### Scenario: 数据库写入失败
- **WHEN** 元信息或正文持久化发生故障
- **THEN** 返回 503，整体回滚，不能出现只有材料记录而没有正文的成功状态

### Requirement: 本班列表查询数据库
系统 SHALL 从持久化数据库查询本班材料列表，并区分无记录和查询故障。

#### Scenario: 班级没有材料
- **WHEN** 授权用户查询没有材料的本班
- **THEN** 返回 200 和空列表，页面展示无材料状态

#### Scenario: 列表读取故障
- **WHEN** 数据库不可用
- **THEN** 返回 503 并显示失败提示，不伪装成空列表或静态演示数据

### Requirement: 密码哈希与服务端密钥
系统 MUST 使用带盐的专用密码哈希存储密码，禁止明文和可逆存储；密钥只放服务端环境变量，不进入客户端、源码或日志。

#### Scenario: 检查账号存储
- **WHEN** 预置账号并检查数据库及登录验证流程
- **THEN** 只有密码哈希及算法需要的参数，没有明文密码；登录通过安全哈希校验而非明文比对

#### Scenario: 检查密钥边界
- **WHEN** 检查源码、前端构建产物、接口响应和日志
- **THEN** 不存在真实密钥、明文密码或返回给客户端的密码哈希；环境示例仅含占位符

### Requirement: 可重复的预置样本
系统 SHALL 提供 A/B 两班、每班一位教师和一位学生及每班一份合成材料与解析正文，账号只属于对应班级；初始密码从服务端环境变量读取并哈希。

#### Scenario: 首次预置
- **WHEN** 在空数据库提供必要初始密码并运行种子初始化
- **THEN** 数据库存在两个班级、四个对应角色账号和两份具有不同正文的材料
- **AND** 四个账号可登录且只访问本班材料，数据库没有明文密码

#### Scenario: 重复执行种子
- **WHEN** 样本初始化成功后修改或删除某条样本，再次运行种子初始化
- **THEN** 不创建重复数据、不覆盖已有修改、不恢复已删除样本

#### Scenario: 初始化缺少凭证
- **WHEN** 首次初始化缺少必要种子密码
- **THEN** 初始化失败，不使用默认密码，不留下部分完成的种子数据

### Requirement: Compose 启动与持久化
系统 SHALL 支持配置必要环境变量后通过 Docker Compose 启动应用和数据库，等待数据库及初始化就绪，数据使用持久卷。

#### Scenario: 干净环境启动
- **WHEN** 在具备 Docker Compose 的环境配置必需变量，执行 docker compose up --build -d
- **THEN** 应用和数据库成功启动，迁移和种子完成，应用 healthcheck 为 healthy，登录页可访问

#### Scenario: 重建服务保留数据
- **WHEN** 上传材料后执行不删除卷的 Compose down/up
- **THEN** 原账号及材料仍存在，种子不覆盖数据，登录后可查询原材料

### Requirement: 匿名健康检查
系统 SHALL 提供不要求登录且不缓存的 GET /health，反映数据库和必要表的可查询状态，并由 Compose healthcheck 使用。

#### Scenario: 依赖健康
- **WHEN** 未登录客户端请求 /health，数据库连接和必要表查询正常
- **THEN** 返回 HTTP 200 与 {"status":"ok"}，不重定向登录页

#### Scenario: 数据库失效及恢复
- **WHEN** 数据库停止或必要表不可查询
- **THEN** /health 返回 HTTP 503 与 {"status":"unavailable"}，不返回内部连接信息或密钥，连续健康检查失败后容器状态为 unhealthy
- **AND** 恢复数据库及表后，/health 恢复 200，后续健康检查可使状态恢复 healthy

### Requirement: R5 材料文件访问
系统 MUST 仅通过 Go 鉴权接口提供材料文件，Nginx 不得将上传存储作为静态目录暴露；下载须验证会话及材料真实班级。

#### Scenario: 猜测上传文件路径
- **WHEN** 未登录或任意用户直接请求 /uploads/猜测文件名
- **THEN** Nginx 返回 404，不返回原文件内容

#### Scenario: 授权与跨班下载
- **WHEN** 本班用户请求材料下载接口
- **THEN** Go 在验证成员关系后返回本班文件
- **AND** A 班用户请求 B 班文件时返回 404，未登录时返回 401

### Requirement: R6 单一同源数据链路
系统 MUST 使用浏览器→Nginx→Go net/http→MySQL 8.0 的唯一数据链路；前端只用相对 /api 路径，开发时 Vite 也将该路径转发到 Nginx，禁止前端数据库连接或直连 Go 端口。

#### Scenario: 开发与 Compose 路径一致
- **WHEN** 分别在 Vite 开发入口及 Compose 入口请求 /api/me
- **THEN** 请求都经 Nginx 到 Go，未登录返回 401，已登录返回本人资料

#### Scenario: api 服务停止
- **WHEN** 停止 api 容器并刷新 Compose 页面或请求材料
- **THEN** 入口返回服务不可用，不能绕过 Go 继续读取材料；已打开页面的下一次请求失败时清空受保护内容并显示不可用状态
